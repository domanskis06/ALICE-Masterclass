# Xi / anti-Xi cascades for Visual Analysis

How the 32 Ξ / Ξ̅ cascades in Strangeness Visual Analysis are produced, merged into existing host events, and regenerated.

| | |
| --- | --- |
| **Exercise** | Strangeness Visual Analysis (`strangeness-visual-analysis`) |
| **Source dump** | [`Xi_params.txt`](Xi_params.txt) (FemtoUniverse candidate log) |
| **Converter** | [`convert_xi_params.py`](convert_xi_params.py) (Python 3, stdlib only) |
| **Host merge** | [`merge_cascades_into_hosts.py`](merge_cascades_into_hosts.py) + [`cascade_host_map.json`](cascade_host_map.json) |
| **Trajectory retrofit** | [`retrofit_cascade_trajectories.py`](retrofit_cascade_trajectories.py) — optional local patch of already-merged hosts (see below) |
| **Legacy ROOT path** | [`../part1/convert_events.C`](../part1/convert_events.C) — original VA hosts (V0s); *not* used for these Xi |
| **Production JSON** | Cascades live inside selected `src/assets/exercises/strangeness/part1/event_{1–20}_{0–14}.json` hosts (no dedicated `*_15` / `*_16` slots; gitignored, built in CI) |
| **Loader** | `StrangenessDataService` (`getEventsInDataset`, `FULL_EVENT_FILE_IDS`) |

Related: EventDisplay cascade picking — [`ci/docs/event-display.md`](../../../../ci/docs/event-display.md). Multi-cascade histogram behaviour — [`ci/docs/changelog-visual-analysis-histograms.md`](../../../../ci/docs/changelog-visual-analysis-histograms.md).

## Why a separate pipeline?

The original VA events under `data/strangeness/part1/events/` were converted from AliVSD ROOT with `convert_events.C`, which uses **TEveTrackPropagator** to bake `trajectory` polylines into JSON.

The 32 new Ξ candidates arrived only as a text dump (`Xi_params.txt`: momentum + position + sign per daughter / bachelor). O2 / open-data do **not** ship trajectory points for these candidates, and we do not have ROOT files for them. Re-running the ROOT macro was therefore impossible for the cascades themselves.

Solution: a Python converter that mirrors the *idea* of `convert_events.C` (uniform \(B_z\), helix steps, same VA JSON schema) without ROOT/TEve, then a **merge** step that appends each cascade into an existing workshop / full host event.

> Demo dataset `0` already contains one historical cascade (`event_0_3.json` from the ROOT pipeline). It is left untouched. The 32 new cascades are merged into workshop datasets **1–20** only.

## Layout

```
data/strangeness/
  part1/                    ← legacy ROOT → JSON (V0s + one historical Xi in demo)
    convert_events.C
    events/                 ← AliVSD ROOT sources
  part1_Xi/                 ← THIS folder: FemtoUniverse → JSON for new Xi
    Xi_params.txt
    convert_xi_params.py
    merge_cascades_into_hosts.py
    retrofit_cascade_trajectories.py  ← optional; patch trajectories in place
    cascade_host_map.json   ← committed seed + host assignments
    README.md               ← this file
    _out/                   ← optional regenerable artefacts (local)

src/assets/exercises/strangeness/part1/
  event_0_*.json            ← demo (unchanged; includes event_0_3 cascade)
  event_{1-20}_0…14.json    ← workshop / full hosts (selected files contain merged Ξ)
                              ← gitignored; regenerated by CI / local pipeline
```

There are **no** production `event_*_15.json` / `event_*_16.json` files. Do **not** commit regenerable `_out/` dumps unless you have a reason.

## Host assignment (32 cascades)

Deterministic map: seed **`20260729`** in [`cascade_host_map.json`](cascade_host_map.json).

| Rule | Detail |
| --- | --- |
| Dataset **6** | Exactly **4** cascades in empty-decay hosts **6, 7, 10, 14** (the only workshop events with `decays: []`) |
| Dataset **20** (Pb–Pb) | Exactly **1** cascade in **`event_20_1.json`**, **kept together** with the existing V0 |
| Other datasets **1–5, 7–19** | At least one cascade each; **9** of them get a second cascade in a **different** event |
| Two cascades in one dataset | Always two distinct host event indices |
| Demo **0** | Untouched |

Navigable lengths (`StrangenessDataService`):

| Dataset | Event count | Notes |
| --- | --- | --- |
| 0 (demo) | 4 | Original demo only; historical Xi at index 3 |
| 1–19 | 15 | file ids `0…14` |
| 20 (full) | 4 | `FULL_EVENT_FILE_IDS = [0, 1, 2, 3]`; cascade is inside event 1 |

### Plan A — demote existing V0s on merge

When a cascade is merged into a workshop host that already has V0 decays (everything except dataset 6 empty hosts and the Pb–Pb exception):

1. Each V0 daughter is copied into `tracks[]` with `type = STANDARD (0)` and `decayId = -1`, **unless** a matching background helix already exists in `tracks[]` (same momentum match as EventDisplay’s `momentaMatchDecayToBackground`).
2. Those V0 entries are removed from `decays[]`.
3. The Ξ cascade is appended to `decays[]` with the next free `decayId`.

Result: only the cascade is an interactive decay; former V0 daughters render as ordinary tracks. No `_suppressedDecays` sidecar — originals are recoverable from ROOT (see below).

**Exception:** `event_20_1.json` keeps its V0 in `decays[]` and appends the cascade beside it.

## Physics / format decisions (locked)

### Species from bachelor sign

| Parent | Bachelor | Pos daughter | Neg daughter |
| --- | --- | --- | --- |
| Ξ⁻ (`pdg_parent` −3312) | π⁻ (`sign` −1, PDG −211) | p (2212) | π⁻ (−211) |
| Ξ̅⁺ (`pdg_parent` +3312) | π⁺ (`sign` +1, PDG +211) | π⁺ (211) | p̅ (−2212) |

Masses used in the converter (GeV/\(c^2\)):

| Species | Mass |
| --- | --- |
| π± | 0.1395704 |
| p / p̅ | 0.9382721 |

### Vertices

`Xi_params.txt` gives a separate `(x,y,z)` per leg. For VA:

- **V0 (Λ) vertex** = midpoint of pos and neg daughter positions.
- **Cascade (Ξ) vertex / bachelor start** = bachelor’s own `(x,y,z)`.
- Cascade daughters (`type` CASCADE) start at the V0 midpoint; bachelor (`type` CASCADE_BACHELOR) starts at the cascade vertex.

### Track types and decay order

Matches existing cascade JSON (e.g. `event_0_3.json`):

| Role | `type` | Value |
| --- | --- | --- |
| V0 daughters | `CASCADE` | 2 |
| Bachelor | `CASCADE_BACHELOR` | 3 |

Decay array order: **`[neg, pos, bachelor]`**, all with the same `decayId` (remapped to the host’s next free id at merge time).

### Helix propagation (TEve-like)

Constants in `convert_xi_params.py`:

| Constant | Value | Role |
| --- | --- | --- |
| `B_FIELD_T` | 0.5 T | Uniform \(B_z\) (same order as `convert_events.C`) |
| `B2C` | \(0.299792458 \times 10^{-2}\) | GeV / (c·T·cm) |
| `STEP_CM` | 1.5 cm | Euler step along the path |
| `MAX_R_CM` / `MAX_Z_CM` | 600 cm | Detector box stop |
| `MAX_PATH_CM` | 500 cm | Cap spirals of low-\(p_T\) tracks |
| `MAX_POINTS` | 2000 | Hard point limit |

**Curvature sign (fixed 2026-07-29):** `propagate_helix`'s rotation must reproduce
the *same* bending sense as `convert_events.C` / TEveTrackPropagator for a given
`sign` — sign=+1 bends CCW, sign=-1 bends CW, verified directly against
`event_0_3.json`'s (legacy, ROOT-generated) proton/pion trajectory arrays. The
naive textbook `du/ds = +(q·B2C/|p|)·(u×B)` rotation bends the *opposite* way
and was shipped for all 32 cascades until this date.

What was wrong vs what was always correct:

| Field / behaviour | Status before the fix |
| --- | --- |
| `sign`, `particleId`, `mass`, `E`, `px/py/pz` | Correct — Calculator rows and track colours matched physics |
| Decay role order (`[neg, pos, bachelor]`) and PDG parent | Correct |
| `trajectory` polylines (visual bend in EventDisplay) | **Wrong** — opposite chirality vs demo / TEve |
| Demo `event_0_3.json` (ROOT / TEve) | Never affected — reference for the fix |

If you touch `propagate_helix` again, re-check chirality against `event_0_3.json` before merging.

**Two ways to apply a helix fix to assets:**

1. **Full regenerate** (source of truth; what CI does): rebuild cascades with `convert_xi_params.py`, restore **clean** hosts from ROOT (no Ξ yet), then `merge_cascades_into_hosts.py`.
2. **Optional retrofit** (local shortcut only): [`retrofit_cascade_trajectories.py`](retrofit_cascade_trajectories.py) recomputes only `trajectory` on already-merged hosts — no ROOT, no re-merge. Does not replace the full pipeline for CI / from-scratch builds.

### Regenerate (local or CI)

CI job `convert_strangeness_events` already runs ROOT convert → `convert_xi_params.py` → `merge_cascades_into_hosts.py` so tag deploys include merged cascades. Production `event_*.json` under `src/assets/.../part1/` are **gitignored**; they exist only after that job (or a local run).

Why **clean hosts** matter: merge is not idempotent. Hosts that already have demoted V0s / appended Ξ fail validation if you merge again. A full re-merge therefore needs workshop/full JSON **as they came from ROOT** (no 32 Ξ yet). CI gets that for free because it regenerates hosts from AliVSD in the same job before merge. Locally, if your `src/assets/.../part1/` already contains yesterday’s merge, either restore from ROOT first or use the optional retrofit below when only trajectories need patching.

From `alice-masterclass-js/` locally:

### 1. Rebuild cascade trajectories

```bash
python3 data/strangeness/part1_Xi/convert_xi_params.py
```

Writes under `part1_Xi/_out/`:

- `xi_cascades.json` — full cascade records + metadata
- `xi_events/event_21_*.json` — optional standalone events (not copied into production)

### 2. Restore clean hosts (required before re-merge)

Merged assets already contain demoted V0s / appended cascades. Re-running merge on dirty hosts fails validation.

To restore **original** workshop / full JSON **without** the 32 merged Ξ cascades, re-convert from AliVSD ROOT:

```bash
# Requires AliRoot / ROOT with TEve + the json.hpp next to the macro.
# From a machine that can run AliRoot:
convert_events("data/strangeness/part1/events", "/tmp/va_part1_json")
# Then copy regenerated event_{1-20}_*.json into
#   src/assets/exercises/strangeness/part1/
# Do not overwrite demo event_0_* unless you intend to.
```

Source ROOT files: `data/strangeness/part1/events/AliVSD_MasterClass_{0–20}.root`. Macro: `data/strangeness/part1/convert_events.C`.

The Ξ cascades themselves **cannot** be regenerated from ROOT — only from `Xi_params.txt` + `convert_xi_params.py`.

### 3. Merge into hosts

```bash
python3 data/strangeness/part1_Xi/merge_cascades_into_hosts.py \
  --cascades data/strangeness/part1_Xi/_out/xi_cascades.json
```

Uses the committed [`cascade_host_map.json`](cascade_host_map.json) (seed `20260729`) unless you pass `--rebuild-map` (avoid in normal regenerations — would reshuffle hosts).

First-time migration from the old empty `*_15`/`*_16` slots could also load cascades from those files; after merge those files are deleted and are not part of the production layout.

### 4. Spot-check

Pick datasets 1, 6, 20; open cascade host events from the map; confirm cascade click → calculator → Ξ / anti-Ξ histogram. Dataset 6 hosts 6/7/10/14 should each show a cascade; `event_20_1` should show V0 **and** cascade.

### Optional: retrofit trajectories only (no ROOT)

When hosts are **already merged** and you only need to fix helix chirality (or any other change that touches solely `trajectory`), skip steps 2–3:

```bash
python3 data/strangeness/part1_Xi/retrofit_cascade_trajectories.py
# python3 data/strangeness/part1_Xi/retrofit_cascade_trajectories.py --dry-run
```

Uses `cascade_host_map.json`, rewrites the three cascade-track `trajectory` arrays in each assigned host, leaves masses / signs / decay structure untouched, never touches demo `event_0_*`. Prefer the full convert → clean hosts → merge path for CI and for any change beyond trajectories.

### Optional converter flags

```bash
python3 data/strangeness/part1_Xi/convert_xi_params.py \
  --input data/strangeness/part1_Xi/Xi_params.txt \
  --cascades-out data/strangeness/part1_Xi/_out/xi_cascades.json \
  --events-out data/strangeness/part1_Xi/_out/xi_events \
  --normalized-out data/strangeness/part1_Xi/_out/xi_params_normalized.json \
  --dataset 21
```

## What future developers should / should not do

**Do**

- Treat `Xi_params.txt` + `convert_xi_params.py` + `cascade_host_map.json` + `merge_cascades_into_hosts.py` as the source of truth for these 32 cascades.
- Keep propagation constants aligned with `convert_events.C` unless you intentionally change the visual language of *all* VA helices.
- Keep cascade `type` / decay order compatible with EventDisplay + calculator.
- When changing counts or host mapping, update `StrangenessDataService` tests and this README together.
- Restore hosts from ROOT before re-merging (merge is not idempotent).
- Use `retrofit_cascade_trajectories.py` only as a local shortcut when already-merged assets need `trajectory` patched without ROOT.

**Do not**

- Re-introduce empty dedicated `*_15` / `*_16` teaching slots.
- Put new heavy physics into `EventDisplayComponent`.
- Expect O2 to give trajectory points for free; if you get better source data (ROOT/VSD), prefer extending / reusing `convert_events.C` for those candidates.
- Confuse this folder with Particle Propagation events (`ci/docs/particle-propagation.md`).
- Overwrite demo `event_0_*` during merge / ROOT restore unless intentional.
